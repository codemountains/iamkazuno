# things メイン画像生成

完成画像は **背景透過・1280 × 1280px・PNG** とする。

## ファイル名

- 完成ファイル名は **`{brand-name}-{product-name}.png`** とする。`brand-name` はブランド名、`product-name` は商品名に置き換える（例: `acme-travel-mug.png`）。
- ユーザー指定の表記を優先し、指定がなければ英字は小文字、空白やパス区切り文字はハイフンにする。ブランド名・商品名が会話や提供資料から特定できない場合は、保存前に不足項目を確認する。
- 連番や `-v2` などの接尾辞を自動で付けない。同名ファイルを保持する必要がある場合は、保存先内の新しいサブディレクトリへ同じファイル名で保存する。

## 作成・加工

- 添付画像や指定されたローカル画像が加工対象なら、その画像を編集する。ローカル画像は先に `view_image` で確認する。背景除去では被写体の形状・色・文字・ロゴを保持する。
- 新規生成ではユーザーの被写体・スタイルの指定を使う。既存画像も被写体の指定もない場合は、何の画像を作るか確認する。
- 画像生成・背景除去には内蔵 `image_gen` を使い、`transparent_background: true` を指定する。プロンプトには「things 用メイン画像、背景を実際に透過、正方形、被写体全体を収める」と明記する。元画像やユーザー指定にない文字・ロゴ・装飾は追加しない。
- 非正方形の画像は、被写体の縦横比を保ち、透明な正方形キャンバスの中央に収める。余白は透明にし、引き伸ばしや意図しない切り抜きを避ける。

## 1280 × 1280px への仕上げ

- 生成時のサイズ指定だけで完了にせず、保存されたファイルの実寸を調べる。必要ならローカル画像処理ツールでリサイズし、アルファチャンネルを保持する。
- macOS では、入力が正方形であることを確認したうえで、次のように新しい PNG ファイルへ出力できる。`input.png` と `{brand-name}-{product-name}.png` は実際のパスに置き換える。

  ```sh
  sips -s format png --resampleHeightWidth 1280 1280 "input.png" --out "{brand-name}-{product-name}.png"
  sips -g pixelWidth -g pixelHeight -g hasAlpha "{brand-name}-{product-name}.png"
  ```

- 非正方形に上記の縦横サイズ指定を直接適用しない。先に透明な正方形キャンバスへ収める。透過の余白を扱えないツールで白背景を足さない。
- 内蔵生成ツールが使えない場合は、その制約を伝える。サイズ調整のために画像生成 API や有料の外部サービスへ自動で切り替えない。

## 完成確認と返却

- 最終ファイルを開き直し、PNG 形式で幅・高さがともに **1280px** であることを確認する。
- アルファチャンネルの有無だけでなく、透明画素と被写体の可視画素が存在することを確認する。全面透明、白背景、市松模様を描いた画像は完成扱いにしない。
- プレビューで被写体の欠け、変形、背景の残りや輪郭の不自然な縁取りを確認し、問題があれば該当箇所を修正する。
- 元画像は保持し、指定された保存先へ新規ファイルとして保存する。保存先の指定がなく、現在のプロジェクト用ならワークスペース内へ保存する。既存ファイルの置き換えを依頼されていなければ上書きせず、上記のファイル名規則を守る。
- 完成画像のプレビューと保存先リンクを示し、「背景透過・1280 × 1280px・PNG」と短く報告する。
