# /picks OG画像生成

既定の仕上がりは **1200 × 630px・不透明背景・PNG**。商品写真を小さめにして、商品間の余白と構図のバランスを優先しながら、多様な商品を載せる。ライトモードの配色を使い、`/picks.` を右下に大きく1か所配置する。ユーザーから別の指定があれば優先する。

## 構図のルール

- thingsが増えることを前提に、掲載数を5点・24点などに固定しない。取得できた画像から色や形のバランスを考えて選び、同じ商品の反復より未掲載の商品を優先する。全件掲載はユーザーから指定された場合に行う。
- 外周での商品画像の見切れを許容する。全商品を枠内に収めるための大きな安全余白は設けず、画面の外まで続く斜めグリッドを全面に敷く。部分表示も構図に使えるため、各商品の全体表示は必須にしない。
- 最終1200px幅では商品の長辺をおおむね60〜80px、中心間隔を90〜115pxにした10〜12列×7〜9行程度から検討する。隣接商品の輪郭の間には20〜30px程度の背景が見える余白を目安に取り、細長い商品も隣の商品に接触させない。元画像のペアやセットは1つのまとまりとして扱い、内部の配置を保つ。件数・縦横比・判別しやすさに合わせて調整し、掲載数を増やす場合もこの余白を保つ。
- グリッド全体を約10〜12度反時計回りに傾け、右上がりの行にする。背景と文字色は `src/styles/global.css` のライトモードに合わせる。現在の背景は `--paper: #f8f7f3`、`picks` は `--ink: #282b25`、先頭の `/` と末尾の `.` は `--accent: #68764d`。商品写真の色は素材を保ち、色や形が偏らないように並べる。
- 表記は末尾のピリオドを含む `/picks.`。既定では右下の余白に、画像の辺と平行な横書きで1回だけ配置する。サイトのワードマークの書体に合わせ、現在は DM Mono を基準にする。最終画像で110px程度・通常の太さ、文字全体の幅が画像幅の約3分の1になる大きさを目安にする。右端と下端から28〜36px程度、近くの商品から24px以上離して読みやすさを保つ。文字の領域にかかる商品を省くなどして、周囲の余白を確保する。

## 素材を用意する

- 素材の指定がなければ、microCMS MCPで `things` の `id`・`name`・`main_image` を取得する。APIスキーマを確認し、一覧が複数ページなら最後まで読む。コンテンツの作成・更新は不要。
- ユーザー指定の画像があればそれを優先する。画像が未登録なら生成対象に含めず、使える素材がない場合はその旨を伝える。架空の商品を補わない。
- 取得した画像はプロジェクト内の `output/og-inputs/` に保存し、商品名・コンテンツID・画像URLとファイルの対応を `manifest.json` に残す。APIキーや認証情報を保存・表示しない。既存の元画像は保持する。
- 内蔵画像生成ツールの参照画像上限（この手順の作成時点では5枚）を、掲載商品数の上限として扱わない。画像が多い場合は、元の写真を変形せず機械的に複数の素材一覧シートへまとめる。各シートの行・列・番号と商品名を対応付け、個々の画像を判別できる解像度を保つ。シート数や1枚あたりの点数は素材数に合わせる。
- 元画像または素材一覧シートを `view_image` で確認する。素材シートは入力準備用であり、最終OGの構図ではない。画像枚数だけを理由に少数の商品へ絞らない。

## 生成する

1. [references/prompt.md](references/prompt.md) を読み、商品数と入力画像・シート内の位置の対応を実際の素材に合わせて埋める。商品数と添付シート数を混同しない。
2. 内蔵 `image_gen` にローカル素材を `referenced_image_paths` で渡し、`transparent_background: false` を指定する。元写真の形・色・印刷を保持し、素材シートの枠・番号・説明文は最終画像に入れない。
3. 構図の参考は [unvalley.me/things](https://unvalley.me/things) のOG。通常はプロンプト内の構図説明で足りる。ユーザーが最新の参考画像との比較を求めた場合は `og:image` を確認する。参考サイトの商品を /picks の素材として流用しない。
4. 採用した生成画像と、素材名を埋めた最終プロンプトをワークスペース内に残す。プロンプトの保存先の既定値は `output/imagegen/og-picks-prompt.txt`。
5. 内蔵生成ツールが使えない場合は制約を伝える。別の画像生成APIや有料サービスには自動で切り替えない。

## 書き出しと確認

- 生成画像の実寸を調べ、**1200 × 630px** に仕上げる。サイズ調整にはローカル画像処理ツールを使える。縦横比を維持して縮小し、比率が異なるときは外周をトリミングする。商品を引き伸ばさない。
- macOSでは `sips -g pixelWidth -g pixelHeight -g format "output.png"` で形式と実寸を確認できる。
- 最終画像を開き直し、小さい商品が画面全体に広がり、隣接する輪郭の間に少し余白があること、背景が不透明で均一なライトモードの背景色になっていること、商品や既存の文字が不自然に変形・反転していないこと、商品同士の重なりがないことを確認する。`/picks.` が末尾のピリオドまで正しく1回だけ表示され、文字色がライトモードに合い、周囲の商品と離れていることも確認する。外周の見切れは不具合として修正しない。
- `manifest.json` と照合し、同じ商品の繰り返しばかりで掲載種類数を水増ししていないか確認する。外周の部分表示と商品の欠落は区別する。全件指定がある場合は部分表示も含めて各素材の利用を確認し、使えていない画像があれば全件掲載とは報告しない。
- /picksのOG作成・更新を依頼された場合は `public/og-picks.png` に反映する。案の作成やプレビューのみなら `output/imagegen/` に保存する。favicon、CMSコンテンツ、公開URL設定は変更しない。デプロイはこのスキルの作業に含めない。
- `output/` は素材・中間生成物・実行記録を置くGit管理外の作業領域。公開に必要な完成画像は `public/og-picks.png` に、再利用するルールとプロンプトテンプレートはこのスキル内に保持する。生成作業やビルドを過去の `output/` の存在に依存させない。
- 完成画像と保存先リンク、サイズ、確認できた掲載種類数、内蔵ツールを使用したこと、最終プロンプトの保存先を短く報告する。
