# microCMS things 作成

商品画像の URL を入力に、画像・ブランド・必要な商品情報をそろえて things を作成する。things と新規ブランドは原則として下書きにし、ユーザーが公開を指示した場合は公開状態で作成する。

## 入力と中断条件

- 商品画像の HTTP(S) URL を受け取り、実際の画像を取得して内容を確認する。ローカル保存した画像は `view_image` で開く。URL の文字列やファイル名だけで画像を判断しない。
- URL が未提供、画像を取得・表示できない、または複数の商品・色・型の候補から対象画像を一意に特定できない場合は中断する。不足情報を短く伝え、この時点では画像生成・アップロード・ブランド作成・things 作成を行わない。別の商品画像を検索して代用しない。
- 商品名とブランド名を会話・提供資料・公式の商品情報から特定する。画像や URL だけで不明な名前を推測せず、不足項目を確認してから進む。
- 説明、カテゴリー、公開指示があるかを確認する。未指定の説明やカテゴリーを自動で補完しない。

## スキーマとブランドの確認

microCMS MCP を使う。最初に `microcms_get_api_list` で接続先の API を確認し、`microcms_get_api_info` で `things`・`brands`、カテゴリー指定があれば `categories` の最新スキーマを読む。フィールドを読み書きする前に確認し、取得できない場合は中断する。スキーマや API 自体は変更しない。

現行のフィールド対応は以下。実行時のスキーマが異なる場合は最新の定義に従う。

| API | フィールド | 書き込み値 |
| --- | --- | --- |
| things | `name` | 商品名の文字列 |
| things | `main_image` | アップロード済み画像 URL の文字列 |
| things | `ref_brand` | brands のコンテンツ ID 文字列 |
| things | `description` | 指示された説明をリッチエディタ用の HTML 文字列にしたもの |
| things | `ref_categories` | categories のコンテンツ ID の配列 |
| brands / categories | `name` | 名称の文字列 |

### 既存ブランドを優先する

1. `microcms_get_list` で `brands` の `id,name` を取得する。`limit: 100` と `offset` を使い、`totalCount` まで全ページを読む。検索や完全一致フィルターの結果だけで不在と判断しない。
2. `name.trim().toLowerCase()` を比較キーにして、入力ブランド名と大文字・小文字を区別せず照合する。保存済みの名前自体は変更しない。`Patagonia`・`patagonia`・`PATAGONIA` は同一ブランドとして扱い、既存の `Patagonia` があればその ID と表記を使う。句読点の除去や略称の展開まで自動で行わない。
3. 同一比較キーで複数の ID が見つかる場合は、ユーザーが指定した ID、次に公式表記と一致する既存レコードを優先する。それでも一意に決まらなければ候補を示して確認する。既存ブランドの改名・統合・削除は行わない。
4. 一致が見つからない場合は、新規作成前に `microcms_get_list_meta` も全ページ読み、通常の一覧にない非公開ブランドの存在を確認する。メタデータには名称がないため、未取得 ID は `microcms_get_content` で取得し、必要に応じてメタデータの `draftKey` を使って名前を照合する。権限不足や取得不能で未確認のブランドが残る場合は、不在と断定せず中断する。
5. 全件確認してもなければブランド公式サイトを開き、原則として英語の公式ブランド名を採用する。大文字・小文字・記号も公式表記に合わせる。運営会社名や販売店名で代用せず、英語の公式表記がなければ公式の原語表記を使う。確認できなければ新規作成前に不足情報を確認する。
6. 公式表記が最初の候補名と異なる場合は、その名前でも既存一覧を再照合する。既存レコードが見つかればそちらを使い、ない場合だけ新規作成用の名前を確定する。

### 説明とカテゴリー

- 説明の登録指示がある場合だけ `description` を含める。提供文の意味を保ち、プレーンテキストなら HTML をエスケープして段落などの必要なタグで包む。説明文の作成も頼まれた場合は、確認できた商品情報から作成し、未確認の性能や仕様を足さない。
- カテゴリー指定がある場合だけ `categories` の名称・ID を取得して照合し、`ref_categories` に指定された既存 ID を設定する。必要なページを読み、同じ ID は重複させない。見つからない・候補が複数ある場合は確認する。カテゴリーの新規作成は別途依頼がある場合に限る。
- 説明・カテゴリー未指定なら対応するフィールドを payload から省く。画像の入力 URL を説明や未定義のフィールドに追加しない。

## メイン画像の作成とアップロード

- [things メイン画像生成スキル](../generate-things-main-image/SKILL.md) を読み、そのスキルに従って入力画像を加工する。依存スキルが見つからなければ中断する。
- 確認済みの元画像、商品名、採用するブランド名を引き継ぐ。元画像を編集対象として渡し、見ていない商品の再現画像を新規生成しない。
- 背景透過・1280 × 1280px・PNG に仕上げ、同スキルで検証して microCMS のメディアにアップロードする。ファイル名・画像処理・保存方法は同スキルを正とする。
- 同スキルが返したアップロード済みの URL を `main_image` に使い、同じ完成画像を再アップロードしない。生成・検証・アップロードが失敗した、または URL が確認できない場合は、ブランドと things の作成に進まず、完成済みのローカル画像と未完了の工程を報告する。

## ブランドと things の作成

入力、参照先、完成画像の URL がそろってから書き込む。登録依頼とこれらの既定値で作成内容が確定していれば、改めて実行確認を挟まない。

| 作成対象 | 公開指示なし | 公開指示あり |
| --- | --- | --- |
| things | `microcms_create_content_draft` | `microcms_create_content_published` |
| 新規ブランド | things と同じく下書き | things と同じく公開 |

- ブランドがなければ、確定した公式名を `brands` の `name` に設定して上記の状態で作成する。成功応答から実際の ID を取得する。既存ブランドを使う場合はその ID を使い、表記や公開状態は変更しない。
- things に `name`、アップロード済み URL の `main_image`、ブランド ID の `ref_brand` を設定し、指示された場合のみ `description` と `ref_categories` を追加する。画像・参照は読み取り時の展開済みオブジェクトではなく、上表の書き込み形式を使う。
- things を公開する場合は、採用する既存ブランド・カテゴリーの状態を `microcms_get_content_meta` で確認する。参照先が未公開の場合は、その公開が既存の指示に含まれるか確認し、必要な指示が得られるまで公開処理を止める。参照先を無断で公開したり、別 ID のブランドを複製したりしない。
- things は最初から指定の状態で作成する。いったん公開して下書きに戻す方法や、`publishedAt` を公開状態の切り替えとして使う方法は取らない。
- 書き込みがタイムアウトして成否不明になった場合は、返却 ID・一覧・メタデータ・メディア一覧などで作成済みかを確認してから再開する。既に成功した画像アップロードやブランド作成を繰り返さず、成否を特定できない間は再作成しない。途中まで作成できた場合は ID / URL と停止箇所を報告し、自動削除しない。

## 完成確認と返却

- 作成した things と新規ブランドは `microcms_get_content_meta` で状態を確認する。things の下書きは `DRAFT` があり `PUBLISH` がない状態、公開は `PUBLISH` を含む状態で判断する。日時の有無だけで判定しない。
- `microcms_get_content` で内容を読み直し、商品名、画像 URL、ブランド ID、指定された説明・カテゴリーを確認する。下書きは取得した `draftKey` が必要なら使う。検証できなければ「作成応答あり・確認未完了」と区別して報告する。
- things の ID と公開状態、ブランド名・ID・既存利用か新規作成か、画像 URL を短く返す。画像スキルの完成プレビューと保存先も引き継ぐ。新規ブランドが下書きならその状態も明記する。
